# AtlaWire parity baseline

Inventory of the existing `bbk` command definitions, library workflows, and test files
on 2026-11-20. This is not a passing parity run. AtlaWire's working-tree baseline was
`53cee89` with uncommitted changes; 221 offline tests passed before the next slice.

Library acceptance must also cover the advertised methods in `bbk/__init__.py`, the
product-specific write functions in `bbk/write.py`, and useful sub-workflows without
CLI commands. In particular:

- **Bitbucket:** PR listing/dashboard, comments, diffs, side-specific files, commit details,
  text and binary reads, and the PR/branch/attachment write workflows.
- **Jira:** identity, statuses and transitions, comment author resolution, comment reads
  and writes, issue rendering, and use of the title cache.
- **Confluence:** page storage, links, spaces/children/CQL, comment creation/deletion, and
  version-aware page edits.
- **Cross-cutting:** auth and endpoint configuration, response types, bounded pagination,
  library errors, CLI output, and write audit before the request. Preserve function, not
  unsafe legacy behavior: explicit authentication mode, no redirect replay, and no silent
  truncation. Keep a record of any caller-visible migration differences.

## Bitbucket catalog candidate

`bbk` already has local project search (`idx.projects`) and a snapshot generator.
The generator gets projects, then asks once per project for repositories to estimate
counts; it uses the length of the first page. Do not preserve that limitation.

Start with live, fully paginated `projects` and per-project `repos`. Then consider a
small, opt-in snapshot that stores project key, repository slug where applicable, short
name, description when available, and canonical browser URL. Interpret “subprojects” as
repositories under projects unless the deployment has an actual hierarchy. Capture only
visible metadata; avoid collecting archives or file content.

Prefer explicit refresh and freshness metadata over a daemon. Refresh all pages before
replacing a previous snapshot; distinguish incomplete and stale results. Do not use an
expired or stale snapshot to hide authorization failure. Partition by verified instance
and credential identity/scope, invalidate on credential changes, and bypass the cache
when the profile cannot establish ownership. Test cross-profile isolation and an interrupted
refresh before using private snapshots. Measure call count and lookup time before adding
automatic on-demand refresh or parallel fan-out.
