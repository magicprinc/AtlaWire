# API surface: what our servers actually serve

Source of truth for routes and query parameters, taken from **each deployment's
own `application.wadl`** — generated by the running code, not by a docs site.

Why not the vendor site: it no longer serves the pinned versions. Confluence
`/rest/v660/` now redirects to `22.x`, and Jira publishes only 10.x. A downloaded
page therefore describes a release we are not running, while the WADL describes
the one we are.

| product | version reported | WADL | sha256 |
|---|---|---|---|
| Bitbucket | 5.10.0 | `bitbucket/source/application.wadl` | see `api-surface-source.json` |
| Jira | 8.22.2 | `jira/source/application.wadl` | see `api-surface-source.json` |
| Confluence | not reported | `confluence/source/application.wadl` | see `api-surface-source.json` |

Confluence exposes no version endpoint over this REST API, so its version is
recorded as unreported rather than guessed; the WADL digest identifies what was
read. The internal host is replaced with `example.com` in every artifact, so they
are safe to review and commit. Credentials are never written.

## Layout

| what | where |
|---|---|
| Provenance and digests | [`api-surface-source.json`](api-surface-source.json) |
| Machine-readable index: every method, its group, file and query params | [`api-surface.json`](api-surface.json) |
| Human-readable per-group reference | `<product>/api/<group>.md` |

Groups follow the route itself, split at a literal segment so no file has to be
loaded whole: `/projects/{key}/repos/{slug}/pull-requests` lands in
`bitbucket/api/projects-repos.md`. Large groups are split automatically; the
current largest file is about 57 KB.

## How this compares with the registry

`api-surface.json` is the server's side. `atlawire operations` is ours. The
difference is the useful signal, and it is reported, not hidden:

| product | server GETs | registered GETs | matched | server-only | registry-only |
|---|---:|---:|---:|---:|---:|
| Bitbucket | 100 | 58 | 58 | 42 | 0 |
| Confluence | 45 | 35 | 35 | 10 | 0 |
| Jira | 173 | 107 | 105 | 68 | 2 |

An earlier version of this table was wrong: the comparison stripped a trailing
path placeholder, which made `/attachment/{id}` equal `/attachment` and merged 15
registered Bitbucket routes into others. Routes are now compared as sets of
variants, and the identity of both difference lists is digested, so a rename
cannot hide behind an unchanged count.

Reading the columns:

- **matched** — the server serves it and we register it. Every one of these
  routes documents query parameters we do not declare yet; that is the
  `query_documented: null` population from `--describe`.
- **server-only** — administrative or system routes (`/admin/*`, `/cluster/*`,
  `/audit/*`, `/application-properties`) that this project excludes on purpose,
  plus a few read routes never implemented.
- **registry-only** — our entries the WADL does not describe at this base path.
  Each has a reason in `api-surface.json` under `not_in_wadl`.

## Regenerate

```shell
python -B tools/fetch_api_surface.py --live      # read both WADLs, redact hosts
python -B tools/build_api_surface_docs.py        # split into Markdown + index
python -B tools/build_api_surface_docs.py --check # fail if any file is stale
```

`fetch_api_surface.py` contacts the configured servers, so it needs `--live` and
working credentials. `build_api_surface_docs.py` is offline and only reads the
stored WADL.
