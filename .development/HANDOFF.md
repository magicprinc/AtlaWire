# HANDOFF — AtlaWire, research readiness

Historical snapshot only. For current scope, next work, and release gates,
start with the [AtlaWire delivery plan](atlawire-delivery/delivery-plan.md#start-here-implement-do-not-re-plan).

Передача сессии другому harness. Состояние на 2026-11-21, HEAD `ff5379c`,
ветка `main` синхронизирована с `origin/main`, рабочее дерево чистое.

Файл намеренно очищен для публичного репозитория: без учётных данных, хостов,
номеров задач и персональных данных. Детальные live-находки остались в истории
сессии и в отчётах, а не здесь.

## 1. Поставленная задача

1. Сделать AtlaWire надёжным **read-only** клиентом для исследования трёх
   self-hosted продуктов: Jira, Confluence, Bitbucket. Агент ищет и читает,
   владелец применяет изменения.
2. Описать в документации отложенные write-операции так, чтобы их можно было
   быстро реализовать позже, но не давать агенту путь записи.
3. Провести аудит публикации: секреты, приватная информация, возможность
   публикации репозитория.
4. Ответить: заменяет ли AtlaWire BBK полностью.
5. Оценить локальную индексацию знаний: нужна ли, ускорит ли, как отслеживать
   устаревание.
6. Выполнить три комплексных исследования на живых серверах:
   активность сотрудника за период; полнота миграции старого продукта на новый
   роутер и используемые БД; полнота Box API и UI API.
7. Оценить результаты как архитектор и руководитель проектов, найти недостатки
   уровня Medium/High и описать их для исполнителя.
8. Свести покрытие read-only API в матрицу для планирования.
9. Закоммитить и запушить результат.

## 3. Принятые решения

| Решение | Обоснование |
|---|---|
| AtlaWire остаётся read-only; мутации отложены | Агент готовит предложение, владелец применяет. В клиенте нет пути записи вообще. |
| Администрирование инстанса — вне области | Пользователи, права, схемы, workflows, webhooks, аудит, лицензии не должны управляться исследовательским CLI. |
| Write-операции описаны в `docs/DEFERRED-WRITES.md` | Сохраняет знания для будущей отдельной библиотеки, не расширяя поверхность риска сейчас. |
| `⌛D` = отложенный кандидат, `❌N` = вне области | Матрица должна показывать, что стоит реализовать, а не только что есть. |
| Строка матрицы — возможность, не endpoint | 125 путей Bitbucket дают 192 операции; иначе матрица превращается в справочник. |
| Сквозной поиск Bitbucket — плагин, не core REST | Реальные ограничения: default branch, индексированные файлы, точные термы, без regex, до 999 файлов. |
| BBK сохраняется до доказанной замены | Критерий: ≥90% представительных задач без вмешательства, ноль критических дефектов. |
| Локальный индекс — пилот вне клиента | AtlaWire не должен владеть кэшем, правами и свежестью; нужен манифест источников. |
| Публикация internal-идентификаторов принята владельцем | Force-push и переписывание истории не выполнялись. |

## 4. План реализации

Порядок и критерии приёмки. Ни один пункт ещё не начат в коде.

1. **Закрыть высокоценные read-gaps** (по одной команде за срез):
   Jira remote links, changelog, transition fields, поиск пользователей;
   Bitbucket last-modified, participants, related/forks, PR merge status;
   Confluence история версий и комментарии страницы.
   Приёмка: offline-тесты + installed-CLI E2E + live read-only проверка.
2. **Доработать частичное:** полный PR diff с безопасным fallback; метаданные
   вложений и связей из raw JSON задачи без лишних запросов.
3. **Решить масштаб матрицы:** добавить read-only admin/config раздел или
   развернуть в endpoint-уровень. Требует решения владельца.
4. **Собрать endpoint-перечень Jira и Confluence** из официальных доков и
   прогнать тем же генератором — сейчас полнота доказана только по Bitbucket.
5. **Disposition-таблица BBK**: каждая CLI-команда, библиотечная функция и
   тест — эквивалент в AtlaWire, адаптированный тест, результат.
6. **Пилот индексации**: manifest (источник, ревизия/коммит, digest, права,
   последняя успешная проверка), тесты на устаревший элемент и отзыв доступа.
7. **Постоянный контроль секретов** в CI: gitleaks с allowlist для двух
   синтетических фикстур.

## 5. План тестирования

Базовая линия — `4afed8f`, 1562 теста. Перезапускать полный набор после
изменений runtime-кода, не после каждой правки документации.

```bash
PYTHONDONTWRITEBYTECODE=1 C:/Python315/python.exe -B -m pytest -p no:cacheprovider -q tests
ruff check src tests checks
ruff check --select S src
ruff format --check src tests checks
pyright --pythonpath C:/Python315/python.exe src tests checks
uv lock --check --offline
```

Live read-only (отдельно, только с согласия владельца, без write-тестов):

```bash
C:/Python315/python.exe -P -B -m atlawire <command> --token-from-env
```

Обязательные проверки для каждой новой read-команды:

- unit-тесты на разбор ответа и на некорректные формы;
- installed-CLI E2E через loopback-сервер;
- пути отказа: серверный cap, заявленное усечение, невалидный UTF-8,
  HTTP 206, отказ от redirect, исчерпание бюджета страниц;
- при ошибке — ненулевой код и **пустой stdout**, без частичной выдачи;
- контракт JSON и TSV не меняется без отдельного решения;
- live-проверка на реальном инстансе с синтетическими фикстурами,
  без записи и без вывода payload'ов.

Для изменений в Jira/Confluence-пагинации добавлять фикстуры с противоречивым
total и повторяющимися идентификаторами: это уже ловило реальные дефекты.

## 8. Важно для следующего агента

- **Окружение:** CPython 3.15 напрямую, без `.venv` для этого проекта.
  Не использовать `uv run` и `uv sync`. Существующий `.venv` не трогать.
  На Windows запускать `.cmd`/`.bat` через shell.
- **Секреты:** только env-пары `ATLAWIRE_<PRODUCT>_URL` и
  `ATLAWIRE_<PRODUCT>_TOKEN`, флаг `--token-from-env`. Не печатать токены,
  не передавать их аргументами, не коммитить. Live write-тесты запрещены.
- **Репозиторий публичный.** Не добавлять персональные данные, внутренние
  хосты и номера задач в новые файлы. Матрица и docs уже очищены.
- **Поиск Bitbucket** — это POST к плагину, не core REST. Только default
  branch, индексированные файлы (~<512 КБ), точные термы, без regex,
  максимум 999 файлов. Не выдавать его за полный обход всех ветвей.
- **Regex-grep** — другой инструмент: читает содержимое на любой ветке через
  архив, не зависит от индекса.
- **Jira `get_issue`** возвращает сырой JSON: links, subtasks и метаданные
  вложений приходят в составе `fields`, но changelog и worklogs — отдельными
  ресурсами, их в ответе нет.
- **Bitbucket `file` на дефолтном коммите** может не найти файл, который есть
  на ветке разработки. Всегда фиксировать ref; для проверки брать коммит,
  где файл реально существует.
- **Инстанс-особенности:** имена статусов смешаны (английские и русские);
  inline-привязка комментария PR может не сохраняться; поиск пользователей
  требует транслитерации кириллицы.
- **Матрица** — снимок `ff5379c`. После изменения возможностей обновлять
  статусы, иначе она начнёт врать. Генератор:
  `.planning/2026-11-20-research-readiness-and-publication-audit/gen_matrix.py`
  (каталог игнорируется Git; при переезде harness убедиться, что файл доступен).
- **Не путать** этот файл с `.development/review/2026-11-20_IMPLEMENTATION_HANDOFF.md` —
  там исторический срез предыдущего этапа.

- Эквивалентность старого и нового роутера не доказана: найденное расхождение
  подтверждено в исходниках, но не проверено на стенде.
- Соответствие «deployed commit → диалект БД → процедура → таблица» не
  установлено; расхождение описаний и SQL подтверждено.
- Полнота Box API и UI API не проверена против runtime-инвентаря маршрутов.
